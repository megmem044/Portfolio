# Toodle API compatibility rules

The OpenAPI document generated by Spring is the source of truth for communication
between the Spring API and the BFF. The generated TypeScript file must be updated in
the same change whenever that contract changes.

## Compatible changes

These changes may remain in the current `v1` contract:

- Add a new endpoint.
- Add an optional request field.
- Add an optional response field when existing clients can safely ignore it.
- Add a new optional query parameter.
- Add a new error response without changing existing successful responses.
- Relax validation while preserving the existing field type and meaning.

## Breaking changes

These changes require a new API version or a documented migration period:

- Remove or rename an endpoint, field, enum value, or supported HTTP method.
- Change a field's type, format, or meaning.
- Make an optional request field required.
- Remove a response field or make a previously present field optional.
- Add a required request field without a safe server-side default.
- Change authentication requirements or successful response status codes.
- Strengthen validation in a way that rejects requests accepted by the current API.

## Versioning policy

The current contract is `v1`. Compatible additions stay in `v1`. A breaking change
must introduce a new route prefix such as `/api/v2` while `/api` continues serving
the existing contract during migration. The old version may be removed only after
all BFF consumers have moved and the removal has been documented.

Every contract change must include:

1. The Spring controller or DTO change and its tests.
2. A successful `OpenApiContractTest` export.
3. Regenerated BFF types from `backend/target/openapi.json`.
4. Updated BFF code and tests when the changed contract is consumed.
5. A passing Toodle CI run.

Do not manually edit `bff/src/generated/spring-api.ts`. Generate it with
`npm run generate:api-types` after exporting the backend contract. Code reviewers
should treat an unexpected generated-type deletion or type change as a possible
breaking API change.
